# 问档 DocAsk 能力归属（2026-11-11 v10 原文交付版）

问档 DocAsk 基于开源 JChatMind 继续开发，保留上游 MIT 许可与版权声明。本文区分继承能力、新增实现和验证边界；代码归属可结合仓库的 docs/provenance.md 核对。

## 哪些能力继承自 JChatMind

- Java、Spring Boot、Spring AI 的 Agent 示例基础，以及 React 前端脚手架。
- Think–Execute 循环、状态机和步骤上限；关闭框架内部自动工具执行，由应用调用工具并回填结果。
- 工具声明与注册框架，及把助手模型、提示词、工具和知识库范围保存为配置的方式。
- 会话和消息持久化、SSE 状态推送，以及 Dockerfile、Compose、Nginx 部署模板。
- Markdown 章节解析、标题向量化与 pgvector 基础检索。

手动 Agent 循环、基础 Tool Calling、SSE 和最初的标题检索不是本仓库从零创造的能力。

## 本仓库新增了什么

**可靠执行与权限控制。** 将对话执行改为 PostgreSQL 持久化队列，消息、快照和任务同事务提交，使用幂等约束、SKIP LOCKED 领取、租约心跳和条件写回。排队任务可在重启后继续领取，已开始的任务中断后不自动重放；提交身份随任务保存，领取及工具调用前复核权限和配置。

**正文索引、来源定位与评测。** 标题向量扩展为正文分块和版本化索引，片段带文档哈希、章节路径、行号及生效版本；用冻结题集对比新旧检索，并保留逐题结果和归因。

**公开资料原文交付。** 新增 sourceAnswer 通道，模型选择本轮来源、连续原文锚点和可选full/partial覆盖状态，服务端完整展示命中片段并编号，对partial显示固定未完整覆盖提示。非法交付有一次修正机会；已有本轮检索来源的故障可给未确认原文参考，未取得既有本轮来源时只给服务未完成提示。空答复不能只因到达步骤上限就被记成成功。

**模型调用边界。** 在继承的手动Agent工具循环之外，新增实际门控显式装配、同步供应商调用期限、共享最多4个传输槽且无等待队列的执行器，以及对内部自动工具执行的默认关闭和显式启用拒绝。工具执行、权限复核与消息写入继续由Agent调用线程管理。

其他新增支撑包括账号与资源隔离、系统模型目录和密钥加密、游客入口、Markdown 原文预览、持久化导入和文件清理队列、历史输入整理、运行追踪与统一检查脚本。

## 公开执行器实际开放哪些工具

公开执行器只装配 KnowledgeTool、getDate、sourceAnswer 和 terminate。知识回答通过 sourceAnswer 的来源选择交付，不接受自由 answer、text、reason 或模型正文绕过；getDate 的成功结果由服务端取得并显示，复合问题还需要继续检索。

sourceAnswer 没有被作为通用组件注入全部账号工具，因此公开体验的新交付策略不会把账号侧普通工具操作悄悄换成另一套语义。旧 directAnswer 与 groundedAnswer 实现及历史消息仍保留兼容，但它们不是当前公开知识问答的交付通道。

## 资料原文与引用能核验到哪一步

模型选择的 citationId 必须属于本轮真实完成的知识检索，原文锚点必须出现在这个命中片段自身，来源还必须通过访问校验。最多接收三项选择，重复来源按实际范围去重；展示编号与完整片段由同一份来源记录生成。

服务端不展示模型改写的陈述，也不拼接模型提供的“资料不足原因”。原文引用块保留片段内的前提、否定和例外，资料不足使用固定说明。仅有短引存在于来源中，不能证明任意改写在语义上成立，所以这里采用明确的原文交付，不宣称完成了语义蕴含判断。

coverage省略或为full表示模型声明完整覆盖，partial只通过固定提示声明尚未覆盖部分，不允许附加自由原因。insufficient:true要求省略sources和coverage，并且发生在真实检索后；这些形状和来源检查都不能证明覆盖声明在语义上成立。

这仍不能保证原文事实绝对正确、资料已经覆盖所有问题，或模型选中的片段总是最相关。历史50题评测中的检索效果与新的交付方式是不同维度。

## 可靠执行当前有哪些保护

| 场景 | 当前处理 |
| --- | --- |
| 重复提交 | 同一身份、会话、幂等键及相同内容取得原运行，冲突内容拒绝 |
| 排队期间重启 | 尚未执行任务继续领取；已开始而结果未知的任务记中断，不自动重放 |
| 取消、租约失效及迟到结果 | 锁定任务后检查状态、取消和租约；消息与成功终态写前写后用数据库当前时刻复核，不满足则回滚 |
| 锁等待及线程中断 | 等待有预算，阻塞后复查；中断、取消和租约失效不进入正常答复回退 |
| 混合检索与交付批次 | 批次先校验，再执行，不能边取证边提前保存最终答复 |
| 20步内始终没有答复 | 以 ERROR 结束，不记空答复成功 |
| 模型故障或交付不合法 | 分类、有界重试或一次修正；已有本轮来源时明确参考，没有既有本轮来源则只给未确认提示 |
| 同步模型调用超期 | 每次请求按当前30秒设置限制调用方等待，取消Future并丢弃晚结果；不包含节流等待或整轮Agent循环 |
| 供应商忽略取消 | 仍占原有传输槽直到返回；共享最多4槽且无等待队列，满时拒绝新传输而不无界增长 |
| 复合问题的参考预算 | 按真实检索组轮流取候选，授权过滤并按来源范围去重，最多三项；不声称完整或相关性已获证明 |

历史验证包括真实PostgreSQL用例、同机双实例强杀、账号与游客访问检查、来源行号核对及保存的真实问答。2026-11-11包含分块进展修复的发布准备稿单元468项中464通过、4项已有Windows环境条件跳过，新增5项分块进展与触发原件回归通过；同发布代码的真实PostgreSQL集成70项全部通过、无跳过。来源选择、条件保留、同步期限、受限执行器、手动工具守卫及检索组分配按对应检查说明，不用本地通过数或运行完成率代替生产和内容质量验收。

没有既有本轮来源且此前尚未完成可读检索时，服务端仍用原始问题执行受限KnowledgeTool检查可读性，但不发布这次服务端读取的任意近邻。已有本轮来源只是模型已实际检索取得资料，不表示sourceAnswer交付或相关性已经通过；参考按实际完成组分配三项预算，也可能含干扰或未覆盖全部子问题。回退不是检索级拒答，也不是已经验证的语义答案。

## 正文分块的进展边界

正文分块属于本仓库扩展的索引链路。一段自身能放进预算、合并下一段却超预算时，旧重叠起点可能停留在原index，循环不断生成同一Range并耗尽堆内存。修复使nextStart严格前进：必要时从first到first加一，当前已输出atom不再重复，同时不跳过未处理atom。保持原件的本地回归与通用段落、重叠检查已验证有界完成及覆盖；实际导入另行核验。这项修复不改变下方历史检索计分数字，也不等于实现混合检索或重排。

## 当前正文检索链路

Markdown 按标题分段，再按约640个估算 token 的窗口、80个重叠切成正文片段。章节路径与正文一起生成 BGE-M3 的1024维向量，记录来源哈希、行号和索引版本。

候选索引核对文档集合、来源哈希与向量模型后原子发布。查询只检索获准知识库的生效版本，按向量 L2 距离取前三条；当前是单路向量检索，没有关键词混合检索，也没有重排。

## 50题检索评测说明了什么

评测使用四份冻结文档，与后来的项目介绍及100题学习资料分别维护。50题包含40道有答案题、10道无答案题，dev为30题、test为20题。下面的命中指标只统计40道有答案题，44是它们涉及的必需证据单元数。

按正文窗口 body-window-v2 口径对两组已保存结果重新计分：

| 指标 | 标题向量检索 | 正文分块检索 |
| --- | --- | --- |
| Hit@1：首条命中至少一项所需证据的题目比例 | 26/40，即0.650 | 35/40，即0.875 |
| Hit@3：前三条至少命中一项所需证据的题目比例 | 34/40，即0.850 | 40/40，即1.000 |
| 前三条结果的必需证据单元覆盖 | 34/44 | 43/44 |
| MRR@3：首个相关结果排名倒数的均值 | 0.738 | 0.933 |

Hit@1 增加22.5个百分点，反映这组样本的首位相关性改善。Hit@3 为1.000不等于全部事实都覆盖，也不等于回答准确率100%。

body-window-v2 是看到旧结果后另行冻结的诊断口径，要求片段覆盖证据正文、包含所需事实，并在片段或章节路径中核对标题。旧 frozen-v1 要求片段行号完整覆盖标题行，在旧口径下标题索引 Hit@3 为0.850，正文索引为0.600，旧结果仍保留。

旧口径下未覆盖的18个必需证据单元中，17个涉及标题边界，1个是真实检索缺口。两组只用保存的结果重新计分，没有重新检索；小语料和事后口径不能证明大规模未知数据上的效果。报告与冻结记录位于 evaluation/runs/body-window-v2-report.md 和 evaluation/datasets/criteria-v2.json。

## 检索仍有哪些缺口

- **排序和干扰**：相似内容可能同时召回，不能宣称正文分块已经消除干扰。
- **检索级拒答**：向量距离阈值开关未启用，历史冻结集的10道无答案题在检索阶段没有被拒绝。公开交付时的不足提示或原文参考，不等于已经建立了可靠的检索阈值。
- **混合检索和重排**：尚未实现，需要新增相应测试后实测，不能预报收益。
- **学习库效果**：100题学习资料提供更多内容和检索场景，尚不能套用历史50题指标作为它的成绩。

## 其他边界与学习资料来源

当前没有逐字正文流式、完整 PDF 或 Word 解析、自动切换备用模型，以及任意外部调用的 exactly-once。原文参考降级不等于切换了另一个模型。跨主机、网络分区、时钟漂移和多模型效果成本对比尚缺验证。

学习资料参考小林 coding 的公开文章独立整理，覆盖 Java、JVM、Spring、MySQL、Redis、网络和操作系统，并保留逐题来源。整理稿不代表原作者官方答案，“高频”表达复习优先级，不表示经过统计的考频排名。

# 问档 DocAsk 产品导览（2026-11-11 v10 原文交付版）

问档 DocAsk 是一个面向文档问答的 Agent。公开体验采用资料原文交付：模型负责检索和选择来源，服务端完整展示选中的检索片段、来源编号及原文位置。你可以查找项目实现，也可以复习 Java 后端与计算机基础。

## 问档 DocAsk 能做什么

1. **对着资料提问**：在已发布的项目资料和八股学习资料中查找知识点，保留问题中的术语、配置项和版本条件。
2. **直接核对原文**：展示本轮检索到的完整片段，来源可打开到文档、章节及对应行号。
3. **查看执行过程**：每次提问保留模型调用、知识库检索、工具调用以及运行状态，便于了解资料是怎样找到的。

项目资料介绍问档的能力、工程取舍与历史评测。学习资料按十个主题整理100道问答，参考小林 coding 的公开文章并保留逐题链接，是独立学习整理稿，不是官方原文或整站镜像。

## 怎样体验一次有出处的问答

先提一个具体问题，例如“问档怎样处理进程中断”或“REQUIRES_NEW 和 NESTED 有什么区别”。系统检索后会展示“资料原文”及来源。阅读时先看段落里的适用条件和例外，再点开来源查看上下文。

模型最多选择三个来源；服务端保留这些命中片段的完整正文，不把模型另写的总结作为答案。因此同一段里的“通常”“仅在某条件下”“不保证”等范围不会在交付时被改成无条件结论。原文较长时可以继续问一个更具体的问题，帮助下一轮定位。

页面上的精选示例是已保存并核对的运行，现场提问会重新检索。原文交付减少了改写和引用配对带来的问题，但资料本身是否正确、选中片段是否足以覆盖问题，仍需结合来源判断。

## 来源编号与资料原文怎样对应

公开执行器使用 sourceAnswer 工具。模型只选择本轮真实检索产生的 citationId，并提供该片段内一小段连续原文作为锚点；可用 full 或 partial 表明所选资料的覆盖范围。正文及编号由服务端生成，模型不能提交自由的 answer、text、reason 或自编引用编号。

服务端核验来源属于本轮检索、仍有访问权限，且锚点确实出现在对应片段中，再对来源去重和编号。展示的正文直接取自同一个来源记录，保留命中片段内的否定、条件和例外；原文中的代码、HTML示例或数字标记不会被当作新的回答引用。

这证明展示内容来自所选原文，不是对任意生成句子完成了语义判定，也不是对资料正确性或完整性的保证。来源片段之外的上下文可以通过原文入口继续查看。

## 只找到部分资料时会怎样

问题包含多个子问题、版本条件或真实业务数据时，现有资料可能只支持其中一部分。模型选择 partial 后，服务端固定显示“本次资料只能支持问题的一部分，未覆盖的内容无法确认”，同时交付有依据部分的完整原文。

full 表示模型认为所选资料覆盖全部问题，省略该字段也按 full 处理；这只是覆盖声明，仍需核对资料，并不是服务端已经证明答案完整。没有可支持部分且实际检索后仍无法确认时，走独立的不足提示，不能把 partial 与不足信号混在一次交付中。

## 资料不足或模型暂时无法完成时会怎样

“本次可用资料不足以确认”需要先发生真实检索，不能只由模型在未查资料时直接宣布。它表达的是这次检索无法确认问题，不是证明整个知识库不存在相关知识。

交付结构或来源选择不符合规则时，系统允许修正一次。模型短暂故障会按错误类型有界重试；仍无法可靠交付时，结果明确标为“自动整理暂未完成，本次未能确认你的问题”。已有本轮检索资料时，可以附上“原文参考”，请你检查是否覆盖问题；参考不是已经验证的完整回答。

故障发生时，如果没有既有的本轮登记来源，不会把任意近邻作为答案发布。如果此前尚未完成可读检索，服务端仍会用原始问题真正调用受限 KnowledgeTool，检查获准资料是否可读；这次服务端读取不会被当作模型已经选定的答复来源，只显示固定未确认提示。已有真实无匹配检索不因回退重复执行。没有可用检索工具、获准知识库或可读检索时报告失败，不把服务故障说成已经证明资料不存在。

已有本轮来源只表示模型实际检索取得了资料，不表示已经提交合法sourceAnswer或完成相关性判断，因此随故障展示的内容始终只是原文参考。

复合问题的参考按真实检索组轮流保留来源，最多三条，减少一组资料占满预算而挤掉另一子问题的情况。这个分配仍可能保留不相关资料或遗漏更多子问题，不能代替相关性与完整性判断。

回退不会重新执行已经完成的工具，也不会改用其他人的权限。取消、租约失效和线程中断会停止后续执行，不能为了展示内容绕过这些状态。

## 日期问题与知识问题能一起问吗

可以。仅问当前日期时，系统通过 getDate 取得真实日期后直接展示；若同时询问日期和知识点，会继续检索知识资料，并在结果中保留实际取得的日期，不会只交一个日期就结束整个问题。

当前日期不由模型记忆推测，知识内容也不会因为同时提到日期就自动变成最新网页信息。公开体验没有实时网页搜索工具。

## 任务排队、取消和重启怎样处理

提问先写入数据库队列，再由后台领取。重试同一提交意图不会另建一次运行。尚未执行的排队任务在服务重启后可以继续领取；已经开始、结果未知的任务在租约到期后标记中断，不自动重放。

取消是协作式的，已发出的外部请求不一定立即停止。正常消息和成功终态写入时都会检查取消状态与租约，避免迟到结果继续写成正常答复。达到20步上限仍没有交付内容时会记为失败；同一模型批次混合检索与最终交付也会先被拒绝，不能出现尚未取到资料就提前落答案的情况。

每次同步模型请求都有调用方等待期限，按当前设置为30秒；超过期限后丢弃迟到结果。它不包括发送前的节流等待，也不是整个多步问题必定在30秒内结束。模型请求的连接与读取设置、受限传输执行器和故障处理见工程案例。

## 公开体验的范围

- 游客无需登录，只能访问已发布资料、精选示例和自己的会话，身份通过浏览器 Cookie 识别。
- 实际工具是 KnowledgeTool、getDate、sourceAnswer、terminate，分别用于检索、日期、原文交付和结束控制，不提供数据库、文件系统或邮件操作。
- 私有知识库和其他用户的会话不在游客访问范围内；提问受频率和并发限制。
- 资料格式以 Markdown 为主，尚未实现完整的 PDF、Word 解析链路。

## 页面上的评测数字代表什么

项目的50题检索评测使用单独冻结的四份文档，衡量那组样本上的检索表现。它不是全站回答正确率，也不是后来新增的100题学习知识库已经取得的成绩。样本、计分口径和新旧结果见《问档 DocAsk 能力归属》的检索评测部分。

资料会随发布更新。退役版本的历史会话正文可以保留，但旧原文入口可能不再可用；精选示例随当前资料更新。产品名称为问档 DocAsk，部分仓库和部署标识仍沿用早期内部代号 exobrain。

## 资料何时可以用于回答

资料需要经过解析、正文分块和索引检查，才能成为有效检索来源。分块过程每次输出后必须继续前进，不能反复产生同一范围；一段合法的小文档也可能暴露这种边界，不能只靠文件大小限制来避免。

新修复确保不能继续合并下一段时，起点仍严格前进，不跳过尚未处理的内容。实际导入和生效索引需要核验，上传请求已经受理不等于资料已经完整入库；生产发布与实际问答结果由发布回执确认。

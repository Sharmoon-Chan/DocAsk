# 问档 DocAsk 产品导览（2026-11-09 版）

本文回答「这个项目能做什么、我在这里能亲自体验什么、哪些能力有边界」。核对日期：2026-11-09。
标注「已实现」指仓库源码中存在对应逻辑；标注「已验证」指有测试或真实运行记录。
没有标注的内容不应被当作能力承诺。

## 用一句话和三个要点说明问档 DocAsk

问档 DocAsk 是一个面向文档问答的 Agent 系统：它检索已发布的资料，给出带原文出处的回答，
并把每一次回答的执行过程持久化下来，供人核对。

三个要点：

1. **回答可核对**：答复里的引用由服务端登记和校验，只能指向本轮真实检索到的资料片段；
   点开来源能看到文档名、行号范围和对应原文。
2. **过程可追踪**：每轮问答都有运行记录，包含模型调用、知识库检索、工具调用和消息落库的
   耗时与状态；失败、取消、中断都如实显示，不会伪装成成功。
3. **执行可靠**：提问先写入数据库任务队列，再由后台领取执行。重复点击发送不会跑两次，
   刷新页面不会丢问题，服务重启时结果未知的任务不会被悄悄重放。

## 三条可以亲自体验的路径

| 体验路径 | 你会看到什么 |
| --- | --- |
| 直接提问 | 一句结论加几条要点，下面挂来源；点开来源可以看到原文对应段落和行号 |
| 查看过程 | 展开「查看过程」，看到这一轮的模型、检索、工具与落库步骤及各自耗时 |
| 试探边界 | 问「重复点击发送会怎样」「点了取消会怎样」「现在还做不到什么」，回答会说明边界而不是编造 |

回答过程中可以点「停止」，这一轮会记为已取消。没有拿到回答时，页面显示「这次没有拿到回答」、
可读的原因和下一步建议；可以重试的情况会给出「重新提问」按钮，直接重发同一个问题。
错误分类只在展开「查看过程」后显示，正文里不出现英文错误码。

## 怎样核对一条回答的依据

- 模型要先调用知识库检索工具拿到资料片段，再组织答复。服务端把本轮真实返回的片段逐条登记，
  答复里的引用只能从这份登记里选。
- 每条来源带文档、章节路径、起止行号、来源哈希和索引版本。点开来源看到的就是这一段原文，
  正文里写不出的行号不会出现在来源里。
- 正文里的编号 `[n]` 由服务端校验、去重并重新编号。正文出现对不上已登记来源的编号时，
  这一轮整体判为无效，不交付正文，也不会补一个看似合理的来源。
- 边界：引用只说明「这段原文确实存在、确实是本轮检索到的」，不保证结论一定被原文支持；
  结论是否准确、有没有过度概括，仍需要读原文判断。

## 能解决的问题与不能解决的问题

能解决：需要从一批文档里快速得到有出处答案的问题，以及需要说明「答案来自哪一段原文」的场景。

不能解决：需要实时联网数据的问题（检索范围只是已发布的知识库）、需要精确数值计算或写入外部系统的
问题，以及把引用等同于事实核验的问题。

## 公开体验的边界

- 游客模式不需要登录，访客身份由浏览器 Cookie 识别；只能看到公开资料和自己的会话，
  看不到其他访客或任何账号的数据。
- 公开体验只开放四个工具：知识库检索、读取当前日期、交付答复、终止。数据库、文件、邮件等工具
  不在公开体验里注册。
- 公开资料由配置白名单明确发布；没有发布的知识库、文档和运行记录，公开接口一律按不存在处理。
- 体验请求有频率限制：同一访客每 3 秒最多提交一次，每小时最多 60 次。
- 游客可以取消自己正在执行的回答；精选示例只读，不可取消、不可续写。

## 首页的精选示例是什么

- 精选示例是**人工复核过的历史运行记录**：每条都是当时一次真实问答保存下来的会话、答复与来源。
- 它们不是打开页面时现场生成的答案；现场提问走的是本轮实时检索与模型调用。
- 只展示复核合格的运行，因此**不代表随机实时回答都能达到同样质量**；实时回答以你自己这一轮的结果为准。
- 较早的示例生成于产品改名之前，答复里可能出现早期名称。

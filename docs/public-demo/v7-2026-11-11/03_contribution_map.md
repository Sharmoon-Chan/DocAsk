# 问档 DocAsk 能力归属（2026-11-11 版）

问档 DocAsk 基于开源 JChatMind 继续开发，保留上游 MIT 许可与版权声明。本文区分继承能力、新增实现和验证边界；资料日期为2026-11-11。具体代码归属可查仓库的 docs/provenance.md。

## 哪些能力继承自 JChatMind

- Java、Spring Boot、Spring AI 的 Agent 示例基础，以及 React 前端脚手架。
- Think–Execute 循环、状态机和步骤上限；关闭 Spring AI 内部工具执行，由应用执行工具并回填结果。
- 工具声明与注册框架；助手的模型、提示词、工具和知识库范围存入数据表，运行时按配置组装。
- 会话与消息持久化、SSE 状态推送，以及 Dockerfile、Compose、Nginx 部署模板。
- Markdown 章节解析、标题向量化和基于 pgvector 的基础知识库检索。

因此，手动 Agent 循环、原生 Tool Calling、SSE 和最初的标题检索不属于本仓库从零创造的能力。

## 本仓库新增了什么

**可靠执行与权限控制。** 将对话执行改为 PostgreSQL 持久化队列，消息、输入快照与任务同事务提交，通过幂等约束、SKIP LOCKED 领取、租约心跳和条件写回管理执行。排队任务重启后继续领取，运行中的任务崩溃后记中断、不自动重放。提交身份随任务保存，领取和工具调用前复核权限；知识库参数按白名单校验，排队期间配置变化则拒绝。

**可核对的回答与评测。** 标题向量检索扩展为正文分块、版本化索引和行号来源；最终答复通过专用通道交付，引用只认本轮真实检索来源，编号不匹配即拒绝。运行事件记录模型、检索和工具调用。自建冻结评测集比较新旧检索，并保存逐题结果和失败归因。

其他新增支撑包括账号与资源隔离、系统模型目录、密钥加密、游客免登录入口、Markdown 原文预览、持久化导入与文件清理队列、历史输入整理及统一检查脚本。

## 引用编号与原文怎样对应

公开体验使用 directAnswer 通道：模型在 answer 参数中写答复，在 citationIds 中列出选择的本轮来源。正文的第n个编号指向该次交付来源数组的第n项，不是检索排名或文档行号。服务端核验来源，再去重并同步调整展示编号；无法匹配的编号会导致整轮答复被拒绝。

引用核验保证“来源存在并且来自本轮检索”，不保证该来源在语义上支持整句话。正文是否概括过度、引用是否支持结论，仍须阅读原文判断。

另一条 groundedAnswer 通道已实现，它要求逐条陈述、来源和原文短引，并检查短引是否出现在对应片段中。这条通道只做过隔离实例验证，公开体验未启用，相关结果不能作为线上质量指标。

## 当前正文检索链路

文档按 Markdown 标题分段，再按约640个估算 token 的窗口、80个重叠切成正文片段；章节路径和正文一起生成 BGE-M3 的1024维向量。片段保存文档哈希、章节路径、起止行号和索引版本。

新索引先创建候选版本，核对文档集合、来源哈希和向量模型后原子发布。查询只检索获准知识库的当前生效版本，按向量 L2 距离取前3条结果。当前仍是单路向量检索，没有关键词混合检索，没有重排。

## 50题检索评测说明了什么

评测语料是4份冻结文档，与后来更新的公开项目资料及新增八股学习资料分别维护。50题包括40道有答案题、10道无答案题；dev 为30题、test 为20题。下面的命中指标只统计40道有答案题，44是这些题涉及的必需证据单元数，不能当作用户量或回答总数。

按正文窗口 body-window-v2 口径对两组已保存检索结果重新计分：

| 指标 | 标题向量检索 | 正文分块检索 |
| --- | --- | --- |
| Hit@1：首条结果命中所需证据的题目比例 | 26/40，即0.650 | 35/40，即0.875 |
| Hit@3：前3条至少命中一项所需证据的题目比例 | 34/40，即0.850 | 40/40，即1.000 |
| 前3条结果的必需证据单元覆盖 | 34/44 | 43/44 |
| MRR@3：首个相关结果排名倒数的均值 | 0.738 | 0.933 |

Hit@1增加22.5个百分点，说明这批样本的首位相关性改善；Hit@3为1.000也不等于答案准确率100%，因为命中一个证据单元不代表覆盖全部所需事实，更不代表生成的答案正确。

body-window-v2 是观察旧结果后另行冻结的诊断口径。它要求片段覆盖证据正文、包含要求的事实，并能在片段或章节路径中核对标题。两边使用保存的逐题结果重新计分，没有重新检索。旧 frozen-v1 判据要求行号完整覆盖标题行，在该口径下标题检索和正文检索的 Hit@3 分别为0.850、0.600；这些旧结果仍然保留。

旧口径下未覆盖的18个必需证据单元中，17个涉及标题行边界，1个属于真实检索缺口。新口径揭示了边界差异，但它是事后定义且语料很小，不能当作大规模、未知数据上的效果证明。报告和冻结记录位于 evaluation/runs/body-window-v2-report.md 与 evaluation/datasets/criteria-v2.json。

## 检索仍然存在哪些缺口

- **排序与干扰片段**：同名或相似内容可能一起被召回。现有题集中出现过干扰片段进入前3条的情况，不能宣称正文分块消除了干扰。
- **无答案拒答**：代码有向量距离阈值开关，但当前未启用；冻结集的10道无答案题在检索阶段没有被拒绝。向量距离的有答案与无答案分布重叠，单独打开阈值可能误拒有答案题。
- **混合检索与重排**：尚未实现。是否改善标识符、错误码、相似段落及拒答表现，需要增加相应测试后实测。
- **新学习资料的效果**：八股题库的来源整理和新库导入不等于检索效果已经通过上述50题评测，不能沿用历史指标作新库成绩。

## 其他明确边界

当前没有逐字正文流式输出、PDF或Word完整解析、自动模型降级，以及任意外部调用的 exactly-once。跨主机、时钟漂移、网络分区和多模型效果成本对比尚缺验证。

模型主动结束但未交付答复时会补一轮，仍没有则记失败；跑满20步上限的分支仍可能记成功但无答复。管理员不能跨用户读取私有资源，属于访问隔离设计。不同向量模型不能混在同一索引中，换模型需要重建索引。

八股学习资料参考小林 coding 等明确标注的公开页面进行独立整理，保留逐题来源，提供学习和追问入口；不宣称这些整理稿是原作者的官方答案，也不把收录题目等同于经过统计的考频排名。

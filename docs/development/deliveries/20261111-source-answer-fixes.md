## 本次实现

- 公开执行器使用`KnowledgeTool`、`getDate`、`sourceAnswer`、`terminate`。`sourceAnswer`只接收本轮来源ID、连续原文锚点与可选full/partial覆盖状态，或真实检索后的不足信号；没有自由`answer`、`text`、`reason`字段。partial由服务端附加固定的未完整覆盖提示，不能把模型覆盖声明当语义证明。
- 服务端从同一登记来源产生完整命中片段和编号，保留片段内的否定、条件及例外；原文中的代码、HTML或数字标记不能冒充本答复的引用。
- 无效来源/结构只修正一次。已有真实检索时可提供明确的原文参考；首次模型失败且未形成可靠选择时，只显示服务未完成/未能确认提示，避免把任意近邻资料当答案。没有检索工具或获准库不能伪装成已经检查过的不足提示，已完成工具不会因修正而重放。
- 20步仍无答复为ERROR；混合取证与最终交付先被拒绝；纯日期由实际工具结果交付，日期加知识点继续检索。
- 普通消息及成功终态写入前后，用数据库`clock_timestamp()`检查取消状态与租约，避免事务等待期间过期却仍提交成功。线程中断、取消、租约失效及未知编程错误不被当作正常内容回退。
- 模型请求按可获得的状态与异常类型分类，对适合重试的失败实行有界处理，保留诊断；原文参考不是换用了备用模型，也不是生成模型已经答对。
- 模型同步请求由共享受限执行器承载，调用方在预算到期后退出等待，取消Future并丢弃迟到结果。最多4个传输槽且无等待队列；供应商忽略中断时仍占原槽，不能不断新建线程或堆积排队。模型内部自动工具执行关闭，工具和消息写入仍由Agent调用线程管理。

原文交付能避免自由改写与引用配对这一步引入的新结论，但不判断源作者是否正确，也不保证选中片段覆盖完整问题。对相关性、证据完整性和检索级拒答仍要继续评测。

### 读取超时不是完整调用期限

I15首模型请求事件持续53.236秒后才以READ_TIMEOUT结束，整轮53.772秒。之前设置的连接5秒、读取30秒，约束的是HTTP连接与读取过程，未实现完整同步调用最多30秒的硬期限。这个观察已保留，不把配置值当作已经验证的总时长保证。

最终本地版通过`ModelCallDeadline`实现每次同步模型请求30秒的调用方期限。共享传输池最多4个槽、无等待队列；迟到结果不会回到Agent继续交付。超时取消不保证供应商立即关闭连接，忽略中断的请求会保留原槽直到实际返回；该限制防止请求线程和等待队列无界增长。槽耗尽会返回安全的不可用诊断，不再无限排队。

该期限不包含发送前的节流等待，也不是整个多步Agent问题的总时限。取消、租约失效和线程中断仍按正常检查点优先停止；真实线上耗时和行为仍须由最终候选与发布回执确认。

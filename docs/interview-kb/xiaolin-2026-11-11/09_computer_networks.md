# 计算机网络高频基础题：10题学习整理

本文是参照小林 coding 官方公开教程独立组织的学习问答，不是官方原文或逐段摘录。选题用于覆盖常见基础机制，不代表经过统计的考频排名；每题附可继续阅读的官方来源。整理日期：2026-11-11。

## Q01 TCP 和 UDP 有什么区别，怎样选择？

**答法：** TCP 提供面向连接、按序交付的可靠字节流，双方维护序列号、确认、重传和窗口等状态。UDP 以数据报为单位发送，不建立同样的连接状态，也不保证到达、顺序或去重。需要完整传输文件和业务数据时常选 TCP；允许部分丢失、重视时效或需要自行控制传输策略时，可考虑 UDP。

**机制与边界：** TCP 的可靠性不等于业务处理成功，收到传输确认只能说明对端协议栈确认了字节，不能证明数据库已经提交。UDP 也不等于应用必然不可靠，应用可以在其上实现确认、重传和拥塞控制，QUIC 就是例子。选择协议要结合消息时效、完整性和额外实现成本，不能只背“一个快、一个慢”。

**来源：** [小林 coding：TCP 三次握手与四次挥手面试题](https://xiaolincoding.com/network/3_tcp/tcp_interview.html)

## Q02 TCP 为什么需要三次握手，两次不行吗？

**答法：** 客户端发送 SYN 告知初始序号，服务端用 SYN 加 ACK 确认并给出自己的序号，客户端再确认服务端序号。三次交互使双方完成序号同步，服务端只有收到最终确认才进入正常的已建立状态。重点是确认这是一轮有效的新连接，不能只概括成“检查两边能否收发”。

**机制与边界：** 网络中滞留的旧 SYN 可能在很久以后到达。两次握手会使服务端过早把历史请求当成新连接；保留最后一次确认，客户端可以识别不匹配的响应并拒绝旧连接。第三个报文可以携带数据，但这不意味着前两次在所有扩展机制下都绝不允许带数据。解释普通握手时，应与 TCP Fast Open 等扩展分开。

**来源：** [小林 coding：TCP 三次握手与四次挥手面试题](https://xiaolincoding.com/network/3_tcp/tcp_interview.html)

## Q03 TCP 为什么通常四次挥手，TIME_WAIT 有什么作用？

**答法：** TCP 是全双工连接，两个方向需要分别关闭。主动方发送 FIN 表示自己不再发送，对端确认后仍可把剩余数据发完，再发送自己的 FIN，主动方最后确认。通常因此看到四个报文；如果被动方没有待发数据，确认与自己的 FIN 可以合并，抓包也可能只有三次。

**机制与边界：** 正常关闭时，主动关闭方在确认对端 FIN 后进入 TIME_WAIT，等待两倍最大报文生存时间，减少旧连接残留报文影响后续连接，并能在对端重传 FIN 时再次确认。不能把 TIME_WAIT 固定归给客户端，服务端也能主动关闭。遇到大量这类连接，应先看短连接、关闭方向和连接复用，不要为减少状态数量直接牺牲正常关闭语义。

**来源：** [小林 coding：TCP 三次握手与四次挥手面试题](https://xiaolincoding.com/network/3_tcp/tcp_interview.html)、[TCP 四次挥手可以变成三次吗](https://xiaolincoding.com/network/3_tcp/tcp_three_fin.html)

## Q04 TCP 的流量控制与拥塞控制有什么区别？

**答法：** 流量控制保护接收方，接收方通告剩余接收窗口，避免发送速度超过应用读取和缓冲能力。拥塞控制保护网络，发送方依据确认、丢包等反馈调整拥塞窗口，避免过多在途数据加重拥堵。两者同时生效，发送上限受接收窗口与拥塞窗口中的较小值约束。

**机制与边界：** 发送方当前还能发送多少，还要扣除已经发出但尚未确认的数据。接收窗口为零时会通过窗口探测等待恢复，并不等于网络断开。经典拥塞算法包含慢启动、拥塞避免和丢包后的调整，具体增长与回退规则取决于实现；不能把某种算法的固定初值或每次减半规则当作所有 TCP 的永久规则。增大接收缓冲区也不能自动消除链路拥塞。

**来源：** [小林 coding：TCP 重传、滑动窗口、流量控制、拥塞控制](https://xiaolincoding.com/network/3_tcp/tcp_feature.html)

## Q05 TCP 粘包是什么，怎样正确读取一条消息？

**答法：** TCP 保留字节顺序，不保留应用每次发送的消息边界。两次发送可能被一次读取拿到，一次发送也可能分多次读取，所以所谓粘包或拆包本质上是应用缺少分帧协议。常见办法是固定长度、分隔符或长度字段；长度前缀协议先读完整包头，再循环读取指定长度的正文。

**机制与边界：** 读取返回了部分数据通常是正常现象，不能因此判定消息损坏，也不能假设一次读取就获得完整请求。分隔符出现在正文里时需要转义；长度字段必须检查范围，避免异常长度导致过量内存申请。关闭某种发送优化只能影响发送时机，无法让 TCP 变成面向消息的协议。HTTP 等应用层协议已经定义边界，应使用正确解析器而非按网络包切正文。

**来源：** [小林 coding：如何理解 TCP 面向字节流协议](https://www.xiaolincoding.com/network/3_tcp/tcp_stream.html)

## Q06 HTTPS 相比 HTTP 多解决了什么，证书有什么用？

**答法：** HTTPS 使用 TLS 保护 HTTP 通信，核心目标是机密性、完整性和对端身份认证。客户端验证服务器证书链及域名，双方协商协议、算法和会话密钥，再用对称密码保护大量应用数据。证书把服务器身份与公钥绑定，不能把证书理解为直接加密全部网页内容的工具。

**机制与边界：** 现代 TLS 常用临时密钥交换协商密钥，不能把早期 RSA 传送预主密钥的流程当作所有版本的实现。证书受信任也不代表网站业务内容真实，更不代表用户已获业务权限。HTTPS 保护传输链路，应用日志、终端泄漏和服务端越权仍需单独处理。对于 HTTP/1.1、HTTP/2，通常先建立 TCP 再协商 TLS；HTTP/3 使用 QUIC，不能套用完全相同的握手层次。

**来源：** [小林 coding：HTTP 常见面试题](https://xiaolincoding.com/network/2_http/http_interview.html)

## Q07 GET 与 POST 的区别，是参数位置不同吗？

**答法：** 首先看方法语义。GET 用来获取资源，应当安全且幂等；安全表示不请求改变服务端资源状态，幂等表示重复执行的预期效果与执行一次相同。POST 把数据交给资源处理，规范不保证幂等。查询参数和请求体只是常见使用方式，不是两者的根本定义。

**机制与边界：** 幂等不要求响应内容每次完全一样，也不禁止服务器记录访问日志。POST 可以配合业务幂等键实现防重复提交，GET 若被写成删除接口则违背了方法语义。POST 请求体并不天然加密，传输保密需要 HTTPS；URL 长度限制也来自浏览器或服务器实现，不能说 HTTP 规范统一规定了一个长度。GET 请求体缺少通用语义，实际接口不应依赖它被所有中间件支持。

**来源：** [小林 coding：HTTP 常见面试题](https://xiaolincoding.com/network/2_http/http_interview.html)

## Q08 HTTP/1.1、HTTP/2 和 HTTP/3 分别改进了什么？

**答法：** HTTP/1.1 默认使用持久连接，减少重复建连，但同连接中的响应顺序会限制并发。HTTP/2 用二进制分帧、流标识和头部压缩，在一条连接上交错传输多个请求。HTTP/3 基于 UDP 上的 QUIC，使用独立的可靠流并结合 TLS，改善连接建立、网络切换和跨流阻塞问题。

**机制与边界：** HTTP/2 的多个流仍共用 TCP 字节流，前面的字节丢失会阻塞后面字节交给应用，因此没有消除传输层队头阻塞。QUIC 将可靠交付限制在各流内部，某个流的数据缺口一般不要求其他流一起等待；但同一流仍需按序交付，各流也共享连接拥塞控制和网络带宽。不能简单说 HTTP/3 完全没有等待，或认为用了 UDP 就没有重传和拥塞控制。

**来源：** [小林 coding：HTTP 常见面试题](https://xiaolincoding.com/network/2_http/http_interview.html)

## Q09 HTTP 强缓存与协商缓存有什么区别？

**答法：** 强缓存依据响应中的新鲜度规则判断能否直接使用本地副本，例如 Cache-Control 的 max-age；在可直接复用时，不必向源站验证。协商缓存则携带资源校验信息请求服务器确认，例如用 If-None-Match 携带 ETag。资源未变化时返回304，客户端继续使用已保存的正文，否则接收新版本。

**机制与边界：** 时间校验也可使用 Last-Modified 与 If-Modified-Since，但精度和修改时间表达可能有限，实体标签通常能更明确地标识版本。no-cache 不是禁止保存，而是复用前需要验证；no-store 才表示不应存储。304 不包含资源正文，不能当成重定向到另一个地址。缓存策略还要区分浏览器与共享代理，涉及用户私有数据时不能只为提速放宽共享范围。

**来源：** [小林 coding：HTTP 常见面试题](https://xiaolincoding.com/network/2_http/http_interview.html)

## Q10 从输入网址到页面显示，主要经过哪些步骤？

**答法：** 浏览器解析地址并检查可用缓存，必要时通过 DNS 获得目标地址，再建立或复用传输连接。以常见 HTTPS 网站为例，完成对应连接与密钥协商后发送 HTTP 请求，服务端处理并返回响应；浏览器解析文档，继续请求样式、脚本和图片，构建布局并绘制页面。这里是按依赖关系概括，不是所有步骤严格串行。

**机制与边界：** 在网络中，传输层区分端口和连接，IP 负责跨网络寻址与路由，链路层负责当前一跳的传递。DNS、连接和资源都有缓存，所以不是每次访问都重新递归解析、握手或下载所有文件；还可能命中代理或 CDN。IPv4 以太网常通过 ARP 查找下一跳的链路地址，并非跨互联网一直查询目标服务器的 MAC。HTTP/3 的连接流程也不同于传统 TCP 加 TLS。
